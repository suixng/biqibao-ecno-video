# 文案方法

## 目标

让观众先看懂角色遇到的具体麻烦，再听懂抽象机制。不要模仿某一条参考文案的句子或段落。

## 结构

1. **钩子**：前 1–2 句交代一个尖锐结果、悖论或冲突；前 2 秒给出值得继续看的问题，不先报术语。
2. **困境**：角色在菜单、排班、账单、订单、房租、仓库或项目中的一个具体选择。
3. **机制**：每一步回答“发生了什么、为什么、谁承担成本”。长稿每 150–250 字新增一个动作、数字、反问或反转。
4. **命名**：观众已经看懂后，才说“这就是 X”。
5. **现实映射**：给 1–3 个同构的现实判断场景。
6. **收束**：给一个检查问题或条件化原则，不把情绪结论写成事实。

## 角色功能

默认比奇堡映射：蟹老板代表经营者或规则制定者；海绵宝宝代表勤奋但信息有限的行动者；派大星代表常见直觉误区；章鱼哥负责现实反问；珊迪代表专业、数据、技术或实验。

替换 IP 时，保持功能关系而非名字。任何角色都可以换，只要其行为、表情和台词仍然清楚服务机制。

## 事实边界

财经、法律、金融、就业和历史题材必须区分事实、例子和推论；避免个性化投资或法律建议。不要编造研究、奖项、数字或人物事件。
